# Canvas authoring coverage

Status: implemented surface and gap ledger  
Baseline: `@figma/plugin-typings@1.130.0`, 2026-07-28

## Scope

This ledger covers persistent, authorable state in the Figma Design document model. It compares
that state with the current `apply_canvas` contract; it does not assign a percentage because Figma
does not define a canonical set of equally weighted capabilities.

The inventory is based on the Plugin API types pinned by this repository and cross-checked against
Figma's current [Plugin API reference](https://developers.figma.com/docs/plugins/api/api-reference/),
[shared node properties](https://developers.figma.com/docs/plugins/api/node-properties/), and
[node types](https://developers.figma.com/docs/plugins/api/nodes/).

An item is excluded only when it belongs to an explicitly out-of-scope editor or feature family,
does not affect the persistent rendered Figma Design result, or is read-only/derived in the pinned
Plugin API. Implementation difficulty, uncommon usage, and the lack of an honest HTML/CSS
equivalent are not exclusion reasons; writable design state in those categories belongs in the
typed Figma extension of the result language.

Excluded:

- FigJam, Slides, Buzz, Widgets, Prototypes, Motion, Make, and editor-session state such as the
  current selection or viewport.
- Figma Draw features: text on a path, transform groups and repeat modifiers, brushes, and dynamic
  and variable-width strokes. Figma documents these in its
  [Draw feature set](https://help.figma.com/hc/en-us/articles/31440394517143-Explore-Figma-Draw);
  Plugin API update 123 identifies the corresponding text-path, transform, and stroke APIs.
- Constraints. Auto Layout provides the sizing and positioning model for this authoring surface.
- Comments, version history, branches, permissions, and other file metadata that the Plugin API
  does not expose as canvas result state.
- `SliceNode`, `exportSettings`, and non-visual handoff/editor metadata such as layer-panel
  expansion, annotations, measurement links, development status, Dev Resources, and plugin
  relaunch data. They do not describe the design rendered on the canvas.
- Read-only or derived fields such as IDs, absolute bounds, inferred Auto Layout, asset detection,
  missing-font status, variable inference, instance override reports, and publish status.

The export and handoff items above are deliberate product boundaries, not authoring backlog gaps.

Pattern Paint is included: although it launched alongside Draw, Plugin API
[update 110](https://developers.figma.com/docs/plugins/updates/2025/05/07/version-1-update-110/)
explicitly states that the beta paint type can be used in both Figma Design and Figma Draw.

Status terms:

- **Supported**: the result can describe and reconcile the complete listed state.
- **Partial**: only the exact behavior described in the status column is supported.
- **Missing**: Figma exposes writable result state, but `apply_canvas` cannot describe it.
- **Excluded**: deliberately outside the scope above.

## Procedural command boundary

Plugin methods are not separate design capabilities when their persistent result is already
describable. Creation, cloning, grouping, Boolean construction, reordering, rescaling, and outlining
a stroke all end in node, hierarchy, geometry, and appearance state inventoried below. The MCP
surface therefore does not duplicate them as commands.

`detachInstance`, same-component `removeOverrides`, and `resetSlot` are also not result fields. They
transform unspecified live state, and invoking them on every retry can discard or recreate
overrides instead of converging to a no-op. A detached frame, explicit component replacement, Slot
content, and supported instance properties remain expressible as desired state; the procedural
shortcuts are deliberately not exposed.

## Node-type boundary

The pinned `SceneNode` union is fully classified below. This prevents a non-Design node from being
silently counted as a gap.

| Disposition              | `SceneNode` types                                                                                                                                                       |
| ------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| In-scope Figma Design    | `FRAME`, `GROUP`, `COMPONENT_SET`, `COMPONENT`, `INSTANCE`, `BOOLEAN_OPERATION`, `VECTOR`, `STAR`, `LINE`, `ELLIPSE`, `POLYGON`, `RECTANGLE`, `TEXT`, `SECTION`, `SLOT` |
| Excluded export boundary | `SLICE`                                                                                                                                                                 |
| Excluded Figma Draw      | `TEXT_PATH`, `TRANSFORM_GROUP`                                                                                                                                          |
| Excluded FigJam          | `STICKY`, `CONNECTOR`, `SHAPE_WITH_TEXT`, `CODE_BLOCK`, `STAMP`, `EMBED`, `LINK_UNFURL`, `MEDIA`, `HIGHLIGHT`, `WASHI_TAPE`, `TABLE`                                    |
| Excluded Widgets         | `WIDGET`                                                                                                                                                                |
| Excluded Slides          | `SLIDE`, `SLIDE_ROW`, `SLIDE_GRID`, `INTERACTIVE_SLIDE_ELEMENT`                                                                                                         |

`DocumentNode` and `PageNode` are not `SceneNode` variants; their in-scope writable document state
is recorded separately below. Prototypes and Constraints are mixins rather than node types and are
excluded by scope.

Publish status is read-only in the pinned Plugin API, and publishing itself is not exposed by that
API; neither is counted as missing writable canvas state.

The [Figma editor](https://help.figma.com/hc/en-us/articles/38231200344599) can use multi-edit to
apply one Slot property across variants. The pinned Plugin API exposes
[`ComponentNode.createSlot()`](https://developers.figma.com/docs/plugins/api/ComponentNode/),
which creates a new Slot and definition together, but no operation that attaches another variant's
Slot to that existing definition. The remaining cross-variant Slot limitation is therefore an API
boundary, not a deliberate reduction of the design model.

## Consequence for the result language

Restricted HTML and deterministic Tailwind utility classes cover the common linear UI composition path. They cannot
faithfully encode every row above without turning class syntax into a second Figma API.

The result language keeps:

- HTML for hierarchy, plain text, linear Auto Layout, basic sizing, and common literal appearance;
- design-system bindings for stable component, variable, and style identities;
- small typed Figma-native fields for state with no honest HTML/CSS equivalent, such as component
  instances, authored reusable components and variant sets, variable modes, masks, intrinsic
  groups, non-destructive Boolean operations, and vector geometry.

Unknown fields must continue to fail closed until their mapping and reconciliation semantics are
implemented.
