# TemPad Dev MCP 运行时参考

[English](RUNTIME.md)

## 运行时更新控制

请在终端中使用与 MCP 客户端相同的环境变量覆盖值运行这些命令。

| 操作                                           | 命令                                                       |
| ---------------------------------------------- | ---------------------------------------------------------- |
| 查看活动版本、暂存版本、切换阻塞原因和查找进度 | `npx -y @tempad-dev/mcp@latest --runtime-update-status`    |
| 查找不超过 npm `latest` 标签的最新兼容稳定版   | `npx -y @tempad-dev/mcp@latest --check-runtime-update`     |
| 确认具体版本和完整性摘要后进行兼容切换         | `npx -y @tempad-dev/mcp@latest --update-runtime <version>` |

经过校验的正式包在 macOS、Linux 和 Windows 上默认采用 `--runtime-updates=stable`。如果旧的非托管 Hub 仍在运行，断开所有 TemPad MCP 客户端再重连，即可启用更新。已有任务和资源存储会保留。Checkout 开发构建和未经校验的本地构建始终使用随包运行时，并拒绝显式启用更新。

切换要求工具契约和指导语兼容、所有客户端均已初始化并启用稳定版更新，且进行中的操作已完成。旧版 Claude hook 可能阻止切换。自动激活还要求客户端支持切换等待。如果有 Claude 客户端连接，其会话须通过验证，hook 也须支持回执与重试。工具调用、传输和原生操作结束并空闲五秒后，supervisor 会重新检查条件。尚未派发的请求最多等待十秒，已派发的写入不会重放。运行中有操作或下载失败时，当前 Hub 会继续服务。兼容切换会保留每个客户端的工具说明。Figma 会重新连接，设计任务可能需要恢复并读回画布。CLI、supervisor、Node.js、浏览器扩展和宿主插件仍按原方式升级或重启。

- 使用 `--runtime-updates=off`，最后一个启用更新的客户端断开后即停止后台检查。
- 将 npm 版本固定并使用 `--runtime-updates=pinned`，可以强制使用启动包的精确版本。如与当前活动的 Hub 冲突，请断开其客户端后再重启。

## 迁移或回退托管 Hub

使用标准 `@latest` 配置时，先断开所有 MCP 客户端，等待 Hub 和 supervisor 退出。MCP 2.0.1 会在下次启动时自动升级托管的 1.x Hub。如果另一个宿主仍保持连接，两个宿主本次都继续使用 1.x。任务、Stop 状态、待确认写入的保护和资源都会保留。如果浏览器扩展低于 1.0.0，请在迁移前升级扩展并重新加载使用 MCP 的 Figma 标签页。

如需回退到留存的 1.0.5，断开所有 TemPad MCP 客户端，等待 Hub 和 supervisor 退出，然后运行迁移命令。

```sh
npx -y @tempad-dev/mcp@2.0.1 --migrate-runtime 1.0.5
```

输入 `update 1.0.5`，核对活动版本后再重连。如果留存的是其他版本，请替换命令和确认语中的版本号。用 2.0.1 执行回退后，正常重启会保留这个选择。准备再次升级时，断开所有客户端，用同一条命令选择已安装的 2.x 版本。如果此前用 2.0.0 回退过且希望继续使用 1.x，请在宿主下次启动前将启动包固定为留存的 1.x 版本。

## 配置

### 工具超时

所有值均以毫秒为单位。设置有效的 `TEMPAD_MCP_TOOL_TIMEOUT` 后，下表中的专用超时默认使用该值，也可分别覆盖。

| 变量                                   |   默认值 | 作用                                                                               |
| -------------------------------------- | -------: | ---------------------------------------------------------------------------------- |
| `TEMPAD_MCP_TOOL_TIMEOUT`              |  `15000` | 常规调用，包括读取节点和选区结构                                                   |
| `TEMPAD_MCP_GET_CODE_TIMEOUT`          |  `30000` | `get_code`                                                                         |
| `TEMPAD_MCP_GET_DESIGN_SYSTEM_TIMEOUT` |  `45000` | `get_design_system` 首次资源发现。续页、精确引用、字体和页面列表读取使用常规超时。 |
| `TEMPAD_MCP_PAGE_STRUCTURE_TIMEOUT`    |  `45000` | 指定页面 ID 或 key 的 `get_structure`，可能需要先加载页面                          |
| `TEMPAD_MCP_APPLY_CANVAS_TIMEOUT`      | `120000` | `apply_canvas` 慢调用告警阈值。达到两倍时，Hub 会报告结果未知。                    |

写入结果未知时，继续写入前须确认操作结束或恢复会话，并成功读取受影响的文件。读取结果须包含至少一个结构根节点或代码结果，或通过 `get_structure` 读取指定页面的快照，空页面也有效。`CANVAS_APPLY_FAILED` 也要求读回，因为回滚未经确认，Undo 边界内的失败以及旧版扩展返回的此类错误同样如此。`CANVAS_APPLY_ABORTED` 表示写入前准备失败，可以直接继续任务。读回要求在 Hub 重启后仍然有效。请先检查画布，避免重放写入。

### 运行时计时

共享同一个运行时的进程应使用相同的设置。所有值均以毫秒为单位。写锁、控制租约和更新空闲窗口须为正整数，最大为 `2147483647`，无效值使用默认值。只缩短过期时间或租约时，默认心跳或续租间隔也会相应缩短。

| 变量                              |  默认值 | 作用                                              |
| --------------------------------- | ------: | ------------------------------------------------- |
| `TEMPAD_MCP_AUTO_ACTIVATE_GRACE`  |  `1500` | 只有一个扩展连接时，自动选择该扩展前的延迟        |
| `TEMPAD_MCP_HUB_LOCK_STALE_MS`    | `60000` | 写锁过期时间，至少为 `2000`                       |
| `TEMPAD_MCP_HUB_LOCK_UPDATE_MS`   | `10000` | 写锁心跳间隔，至少为 `1000`，至多为过期时间的一半 |
| `TEMPAD_MCP_CONTROL_LEASE_MS`     | `10000` | 运行时控制租约，至少为 `100`                      |
| `TEMPAD_MCP_CONTROL_RENEW_MS`     |  `2000` | 控制租约续租间隔，至多为租约的一半                |
| `TEMPAD_MCP_RUNTIME_AUTO_IDLE_MS` |  `5000` | 具备更新条件后，自动激活前所需的空闲窗口          |

### 扩展连接和资源

| 变量                                      |                        默认值 | 作用                                                                      |
| ----------------------------------------- | ----------------------------: | ------------------------------------------------------------------------- |
| `TEMPAD_MCP_MAX_EXTENSION_CONNECTIONS`    |                          `16` | 单个 Hub 同时连接的浏览器扩展数量上限                                     |
| `TEMPAD_MCP_MAX_PAYLOAD_BYTES`            |                     `4194304` | 扩展发来的 WebSocket 消息字节数上限。只可调低协议上限，无效值使用默认值。 |
| `TEMPAD_MCP_MAX_ASSET_BYTES`              |                     `8388608` | 捕获的资源和截图的字节数上限                                              |
| `TEMPAD_MCP_MAX_ASSET_STORE_BYTES`        |                   `268435456` | 本地资源存储总字节数上限                                                  |
| `TEMPAD_MCP_MAX_CONCURRENT_ASSET_UPLOADS` |                           `4` | 并发资源上传数量上限                                                      |
| `TEMPAD_MCP_ASSET_TTL_MS`                 |                  `2592000000` | 从最近一次访问到清理的毫秒数，设为 `0` 可禁用                             |
| `TEMPAD_MCP_ALLOWED_EXTENSION_ORIGINS`    | 任意合法的 Chrome 扩展 Origin | 以逗号分隔的精确 `chrome-extension://...` Origin。无效值会阻止启动。      |

Hub 接受来自 Chrome 扩展 Origin、目标为根路径的 WebSocket 握手。如需限制到本次安装，请将 `TEMPAD_MCP_ALLOWED_EXTENSION_ORIGINS` 设为浏览器中显示的 TemPad Dev 扩展 Origin。Origin 校验和每个进程的资源 capability 可降低跨 Origin 的 loopback 滥用。其他系统用户先占用端口等本机进程风险见[本地 MCP 威胁模型](../../docs/security/local-mcp-threat-model.md)。

### 目录

| 变量                     | 正式版默认值                                                  | 用途                 |
| ------------------------ | ------------------------------------------------------------- | -------------------- |
| `TEMPAD_MCP_RUNTIME_DIR` | 临时根目录下的 `run`                                          | 本地运行时文件       |
| `TEMPAD_MCP_STATE_DIR`   | `~/.tempad-dev/state`，显式指定运行时目录时使用其中的 `state` | 持久化任务和反馈状态 |
| `TEMPAD_MCP_LOG_DIR`     | 临时根目录下的 `log`                                          | 进程和启动日志       |
| `TEMPAD_MCP_ASSET_DIR`   | 临时根目录下的 `assets`                                       | 本地资源存储         |

即使 Hub 使用不同的运行时目录，也会独占锁定状态和资源目录，直到进程退出。旧版本发布时尚无这些存储锁，请为同时运行的版本配置独立的存储。Unix 上，所有覆盖后的目录必须属于当前用户，仅允许该用户访问（例如权限为 `0700`），且必须是实际目录。

## 启动与连接排查

- **客户端无法连接。** 先看 stderr。首次连接前，临时故障可在孤儿 Hub 锁租期（默认 60 秒）加启动时间的窗口内重试。桥接成功过后，临时故障会持续重试。权限、信任或无效桥接错误连续出现三次时，CLI 会退出。解决报错后重新连接。
- **Hub 启动后迟迟未就绪。** 在日志目录中查找 `startup-mcp-*.log`。每个进程最多记录 1 MiB，从 `npx` 下载结束后启动 CLI 开始，记录校验、缓存写入、锁等待和运行时启动，直到首次就绪或失败。常规进程日志每个文件保留最新的 10 MiB，并标记截断的记录。进程退出后，日志距最后一次写入满七天即清理。
- **Linux 报告运行时路径不可信或冲突。** 当 `<系统临时目录>/tempad-dev` 属于当前用户且权限为 `0700` 时，运行时默认使用它。旧根目录不安全时，会改用 `<系统临时目录>/tempad-dev-<uid>`，创建该私有目录后会优先使用它。两个根目录均有当前用户的 Hub socket 或锁，或不安全的根目录中有当前用户的 Hub socket 或锁时，会停止自动迁移。请关闭已有运行时，修正所有者和权限。Unix 客户端和生命周期 hook 会在连接前检查 socket 的类型、所有者和私有权限。其他平台使用 `<系统临时目录>/tempad-dev`。显式目录覆盖优先。
- **Windows 拒绝默认运行时根目录。** 托管存储和命名管道通过 ACL 将访问限制在当前用户、SYSTEM 和 Administrators。对于当前用户拥有、只通过继承将访问权限授予其他账号的默认正式版根目录，MCP 可以将其改名为 `tempad-dev.legacy`，并在原路径创建私有目录。旧文件留在备份中。存在运行锁或同名备份时会停止恢复。如果启动错误要求手动改名，请先停止所有 TemPad MCP 客户端，再改名并重连。

## 任务存储恢复

### 写入可能仍在执行

在原操作得到确认前，即使重启 Hub，该文件仍禁止写入。重新连接原来的 Figma 浏览器，让 Hub 验证操作完成、标签页关闭或文档替换。再次写入前须读回文件。如果原浏览器无法重连，请在交互式终端检查文件和执行环境并解除阻塞。

```sh
npx -y @tempad-dev/mcp@latest --runtime-status
npx -y @tempad-dev/mcp@latest --resolve-runtime-block <block-id>
```

关闭原执行环境后才能确认。命令会注销此次执行并保留 Stop 保护，之后须显式恢复任务并读回。命令无法停止远端代码、重放请求或重置任务存储。

### 无法读取任务快照

如果快照由较新的 Hub 写入，请升级运行时并重连所有客户端。如果现在的 Hub 仍拒绝读取，错误会指出受影响的路径。读取功能仍然可用，画布写入在重启后依然会被阻止，以保留 Stop 保护。Hub 会尽可能将无法读取的状态保存在 `.corrupt` 文件中。

如需从备份恢复，请断开所有 MCP 客户端，等待 Hub 退出，并保留原快照和任何 `.corrupt` 文件的副本。验证替换文件是包含最新 Stop 保护的完整快照，然后原子替换到原路径并重新连接。旧 Hub 隔离的 `.corrupt` 文件在升级后可能是有效的新格式快照，恢复前须确认内容和时间。旧备份和残留的 `.tmp` 文件可能早于某次 Stop 操作。

如果没有可信的完整快照，请断开所有客户端，等待 Hub 退出，再运行恢复命令。

```sh
npx -y @tempad-dev/mcp@latest --recover-task-storage
```

请传入与 MCP 客户端相同的 `TEMPAD_MCP_STATE_DIR` 和 `TEMPAD_MCP_RUNTIME_DIR` 环境变量覆盖值。命令依据终端环境确定快照路径，即使拒绝恢复也会显示该路径。请核对路径是否指向受影响的存储。恢复命令会拒绝仍有活跃写入者或可正常读取的存储。它会把原文件保存到输出的备份目录，并创建新一代任务状态。请保留备份和隔离标记。

所有旧任务继续失效。旧评论无法恢复执行，写入仍须绑定任务。后续每次 `begin` 都必须提供 `recoveryGeneration`，包括新会话和 Hub 重启之后。被拒绝的 `begin` 会在 `_meta.recoveryGeneration` 和错误文本中提供该值。每个新任务都必须先读取目标才能写入。新一代任务的历史从空白开始。请通过已验证的快照或本恢复流程来保留 Stop 保护。
